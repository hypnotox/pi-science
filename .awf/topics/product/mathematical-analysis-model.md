# Mathematical analysis model

The mathematical analysis model separates public syntax and analysis semantics from backend-specific representation.

## Shared backend-independent model

Accepted mathematical syntax normalizes into one internal model. Parsing, cost semantics, and analysis policy remain separable from SymPy-specific representation, which neither defines the public protocol nor owns product policy. SymPy is the established algebra, rendering, and verification backend behind checked, resource-bounded seams; prefer extending these seams over recreating backend algebra, and never treat a general or unverified CAS result as supported behavior, proof, or qualification.

## Equation dependency work

Direct Python equation systems resolve unique named producers into a deterministic acyclic graph. Each equation is charged once per local output-domain point, downstream references reuse that result, and inclusive bounded sums recursively bind each finite direct-work iterator across operation categories, opaque work, and primitive invocations. For a proved integral range, cardinality is `max(upper - lower + 1, 0)`; body work scales by it and mathematical reduction contributes `max(cardinality - 1, 0)` additions. Aggregate abstract work excludes loop control, indexing, bound evaluation, storage, scheduling, hardware, and runtime effects. Acyclic affine output domains aggregate in reverse stable dependency order while preserving LHS coordinate order. The partial bounded equation-local constraint family intersects mandatory base domains with named normalized affine bounds through analyzer-owned `Min`/`Max`; it drives cardinality and work without making TypeScript a mathematical-policy owner. A globally proved-empty local intersection is a request error, undecidable compatibility remains unresolved, and a valid scenario-specialized empty intersection has exact zero cardinality and work. Bounded intrinsic, submitted, and predecessor-domain facts close supported affine direct-work sums under the existing 4096 reasoning and work budgets. A populated symbolic `Sum` owns its iterator exactly when closure is unavailable; unresolved cardinality, ordering, or finiteness remains explicit, while unresolved primitive costs remain explicit.

## Assumption-aware query reasoning

The Python query evaluator, not Pi transport, retains declared domains and global assumptions, and an equation-targeted answer records only the selected equation's consumed local effective-domain constraints; local constraints never enter another equation or a top-level query. Answers conservatively identify used assumptions, relevant unsupported assumptions, conditions, blockers, and proof status; localized blockers distinguish failed supported families, structural or resource bounds, ambiguous axes, and missing preconditions. Valid unsupported questions remain unresolved or inapplicable results rather than transport failures or implied broader evaluator support. Python sequentially resolves a derived target only from an earlier proved or proved-under-assumptions closed-form answer with checked evidence and exactly one candidate, preserving request/result order without a general query scheduler and inheriting deduplicated conditions and relationship provenance under public bounds. Source verification evidence remains on its source rather than becoming a downstream assumption; inherited qualification cannot be strengthened, and qualification overflow is unresolved. Missing eligibility is an inapplicable result, never submitted-target fallback. Direct `closed_form` also supports one partial finite-polynomial nested `Sum` tree. At each level, coefficients may use exact rationals, declared symbols, and outer binders, but not symbolic rational-function coefficients or an active-binder denominator; bounds are finite, self-independent affine integers. Python measures degree after reasoning and verified inner replacement, proves ordered-or-empty ranges, uses collision-free backend binders, independently verifies bounded antidifference witnesses, and reparses every witness into the restricted model without escaped temporaries or bounds. Proved-empty ranges close to zero before backend reversed-range behavior applies. Canonicalization extracts exact rational sign and content, merges factor multiplicities, orders factors through the restricted renderer, and publishes only an independently identity-checked bounded result. Direct equivalence, properties, limits, and asymptotics do not invoke this route; an explicit derived target makes the verified candidate available to those consumers.

## Candidate comparison

Comparison expands only mapped acyclic producers for bounded semantic equivalence, retaining submitted graphs for reuse-aware aggregate abstract work that charges named producers once per output-domain point and reuses downstream references. It returns qualified abstention for incompatible interfaces, unsupported expansion, equivalence, costs, or ordering; it does not compare scenarios, resources, runtime, machine arithmetic, rewrites, searches, AFMM completeness, or global optimality.

## Exact values and infinity

Query and scenario finite scalars are bounded exact rationals, including exact decimal syntax, while `oo` and `-oo` are explicit mathematical infinity. Infinite mathematical expressions remain analyzable but never imply finite direct-evaluation work.

## Aggregate-work dominance

Direct Python decomposes only retained original aggregate abstract work into bounded reduced-rational signed power terms on one active axis. For supported work it collects nonzero numerator powers over one shared reduced denominator, verifies exact reconstruction, and compares absolute magnitude while retaining signed renderings. Exact real or integer cells partition at pairwise squared-magnitude roots, denominator poles, and active-domain boundaries, then coalesce adjacent equal regions. Unsupported exponentials, opaque aggregates, rewrites, runtime/resources/scheduling/optimality, and global relevance remain excluded.

## Bounded optimization

Python runs one fixed `bounded_goal_v1` fair breadth-first monotonic depth-two search over every shipped exact lane: repeated-structure, call and reciprocal reuse, factoring, redundant-operation removal, iterator-invariant hoisting, compatible cross-equation sharing, Horner reformulation, and `finite_polynomial_sum_v1`. The exact-algorithmic lane shares the checked bounded nested finite-polynomial derivation but replaces only its unique maximal `Sum` tree inside the preserved target shell. Each family has one schema-enforced exact provenance tier, the plan summary tier equals its final trace-step tier, and a new algorithmic family requires separate approval. Python independently rederives and correlates each algorithmic identity against its replayed parent and rederives every retained identity for direct original-to-final proof; backend candidates and query envelopes are not proof. Each accepted transition replays, proves parent equivalence, and strictly reduces the selected objective; the root is not a result. The weighted objective applies the five retained operation weights and fixed coefficient one to known opaque primitive work; unknown, unresolved, or non-finite work blocks optimization, and all-one weights reproduce `unit_work_v1`. Python publishes only verified positive whole-computation reductions under the submitted domain.

Canonical complete states deduplicate only search, while caller-facing candidate order and policy-free identity remain intact. Search keys capture-avoidably normalize `Let`, `Sum`, output-index binders, and equation order across the complete computation context while excluding policy and history. Built-in family lanes and canonical parent states use deterministic round-robin scheduling; duplicate states retain the shortest then deterministically least trace. Fixed per-depth and whole-request limits cover states, parents, transitions, reanalyses, proofs, transformations, and work comparisons. Search records actual families, fixed depth, resource limits, and completion separately from the ranked output prefix. It publishes only bounded target-local missing-cost, domain/cardinality, and evaluator-limit blockers already observed during generation or verification; diagnostics perform no additional search or proof work. Pi protocol v17 strictly validates, correlates, and presents the goal, scope, `strict_improvement` claims, result classification, blockers, one- or two-step traces, candidates, and typed failures without deriving sums or recomputing mathematics, policy, applicability, scheduling, ranking, or refusal reasons.
