# Plan: Implement opt-in exact algorithmic finite-sum optimization

## Goal

Let callers explicitly enable the checked nested finite-polynomial Sum replacement and receive a complete independently verified exact-algorithmic optimization plan through protocol v16. Preserve existing algebraic optimization and all nonoptimization analysis when the family is absent or ineligible; do not widen the closed-form family, add diagnostics, or claim runtime behavior.

## Architecture summary

Extract the ADR-0012 nested finite-polynomial derivation into one internal checked result consumed by both query projection and optimization, while keeping query results informational and making optimizer proof an independent invocation over replayed states. The optimizer adds one opt-in family lane for the unique maximal supported Sum tree, replaces only that tree inside its existing target shell, ordinary-replays the complete candidate, and admits it only after parent-relative proof and positive whole-computation selected-objective comparison. Private trace provenance lets final acceptance independently reverify every algorithmic identity from the original state before the common original-to-final proof and comparison.

Extend optimization input with the family-specific `enabled_algorithmic_families` list and extend every trace step and summary suggestion with a schema-correlated transformation tier. The family participates in the existing canonical fair depth-two search, budgets, deduplication, ranking, and output projection only when enabled; mixed algebraic and algorithmic traces remain bounded by the same proof rules. Migrate Python, generated schema, adapter, strict TypeScript validation, presentation, tests, current-state claims, and active documentation atomically to protocol v16. No preparatory general rewrite, aggregate IR, or query-envelope dependency is introduced.
