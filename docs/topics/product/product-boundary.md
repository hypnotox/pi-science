# Product boundary

The product boundary separates symbolic mathematical analysis from empirical and implementation-execution workflows.

`pi-science` analyzes agent-formulated symbolic or formula-oriented computation and reports abstract mathematical metrics, normalized interpretation, structure, scaling, bounds, repeated-expression extraction diagnostics, explicitly requested bounded mathematical queries, and unresolved quantities. Direct Python and Pi report bounded aggregate-work term dominance on one declared axis. It does not evaluate a submitted formula to produce the value that formula represents. Query-derived candidates are informational rather than replacement implementations or work claims. Python and Pi candidate comparison is available for exactly two explicitly mapped mathematical candidates under reuse-aware aggregate abstract-work semantics that charge named producers once per output-domain point; it establishes mapped semantics before a qualified work relation.

Optimization is a separate explicit goal operation, never passive ordinary-analysis advice or an informational query. Python interprets a preserve-all exact-symbolic goal over the submitted domain, runs fixed bounded depth-two search over every shipped exact lane, verifies positive selected-objective whole-computation reductions, classifies the observed population, and reports bounded localized blockers. Pi protocol v17 validates, correlates, and presents that Python-owned result without recomputing policy. The operation returns replayable complete candidates and `strict_improvement` claims, not source edits, family selection, general rewriting, best-candidate or global optimality, runtime prediction, finite-precision equivalence, numerical optimization, or empirical evidence. Dataset statistics, source-to-model inference, experiment orchestration, implementation benchmarking, and physical validation remain outside the core analyzer. Future target-aware exact symbolic costs, approximate numerical optimization, and empirical profiling remain separate lanes whose evidence cannot substitute across boundaries; each requires a later decision before implementation. Formula-to-code remains an open future direction outside the current formula package scope.
